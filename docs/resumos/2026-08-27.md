## Como o código do Lovable saiu de lá

O sync com GitHub é recurso pago — a aba de código fica em "Read only". Então
o caminho foi outro:

- Os arquivos de código saíram um a um pelo botão de download da aba de código
- **As imagens saíram por URL direta**: clicar em "Download" numa imagem abre
  ela numa aba, e daquele endereço dá para baixar o arquivo original

Vieram os arquivos que *são* o site: `styles.css`, a home, o `Loader` e o
`WebBackground`. O esqueleto (router, servidor, 50 componentes do shadcn que a
página nunca importa) ficou para trás porque não é usado.

O projeto agora é `PROJETOS/spider-portfolio`, em Vite.

## As descobertas do dia

### A faixa de tecnologias era uma mentira fácil

O Lovable tinha escrito WebGL, Canvas e Figma à mão na faixa que corre embaixo
do hero. Ninguém lê aquilo item por item — é o lugar mais fácil de inflar um
currículo sem ninguém notar. Agora ela é gerada de `content/skills.ts` e só
mostra o que você declara como sólido.

### A imagem pesava 5,7 MB para aparecer em 320 pixels

O retrato original tem 2048×2048. Ele aparece dentro de um círculo de 320px.
Eram 5,7 MB baixados para exibir 320 — num site que anuncia "PageSpeed 95"
como prova de competência. Convertido: **71 KB**, sem diferença visível.

### Três bugs que só apareceriam impressos

O currículo saía **sem nome, sem e-mail e sem telefone**. A causa: eu escrevi
`header { display: none }` no CSS de impressão para esconder o cabeçalho do
site, e o seletor pegou junto o cabeçalho de identificação de dentro do
currículo. Um PDF chegando no recrutador sem dizer de quem é.

Antes disso, ele saía **preto sobre preto** (o container de fundo escuro
continuava pintado) e depois **com seis páginas em branco** (esconder com
`visibility` mantém a altura do elemento).

### A abertura podia nunca sair da frente

O Loader contava ticks de um `setInterval`. O Chrome estrangula timers em aba
de segundo plano — e abrir link em nova aba é o gesto mais comum que existe
com um portfólio. A abertura de 2 segundos virava 10 ou mais.

Agora ele mede tempo decorrido em vez de contar ticks, e tem um teto absoluto:
passou de 4 segundos, a cortina sai de qualquer jeito. Nenhuma animação de
entrada vale uma página que não abre.

### O mesmo problema atingia o conteúdo

Os textos entram com um efeito que os mantém invisíveis até o observador
marcá-los. Se o JavaScript não roda, ou se o observador é congelado, a página
fica em branco para sempre. Resolvido com uma classe escrita antes da primeira
pintura (sem JS, nada é escondido) e um prazo de segurança.
